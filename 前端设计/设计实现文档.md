## 一、技术栈适配对照

| 设计文档（React） | 当前项目（Vue 3） | 适配策略 |

## 二、API 接口适配 —— 设计文档 → 项目实际接口

> **路径规则**：设计文档接口以模块名为前缀（如 `/auth/...`、`/content/...`），项目实际接口统一前缀 `/api`，按资源命名。

### 2.1 认证模块：`auth` → `/api/users`

| 设计文档接口 | 实际项目接口 | 差异说明 |
|---|---|---|
| `POST /auth/login` | `POST /api/users/login` | 设计：`{ email, password }`；项目：`{ name }`（无密码桌面场景） |
| `POST /auth/register` | `POST /api/users/register` | 设计：`{ name, email, password }`；项目：`{ name, current_goal?, preference?, level? }` |
| `POST /auth/refresh` | — | 不需要（无 JWT，无刷新令牌） |
| `GET /auth/me` | `GET /api/users/:id` | 设计从 token 解析；项目通过 userId 查询 |
| `PATCH /auth/me` | `PATCH /api/users/:id` | 字段映射：`educationLevel`→`level`，`subjectPreferences`→`preference` |
| `POST /auth/google` | — | 不需要（桌面应用不接入第三方 OAuth） |
| `POST /auth/apple` | — | 同上 |
| `POST /auth/forgot-password` | — | 无密码机制 |
| `POST /auth/reset-password` | — | 无密码机制 |

### 2.2 用户模块：`users` → `/api/users`

## 十一、关键设计决策记录

| 决策 | 理由 |
|---|---|
| 创建/编辑页面用 Dialog 而非独立路由 | 减少路由数量，Element Plus Dialog 已满足需求 |
| 维持名称登录（无密码） | 桌面 Electron 应用，本地数据库，无远程认证需求 |
| 维持 Hash 路由模式 | Electron `file://` 协议不支持 HTML5 History 模式 |
| 维持 CSS Variables 而非引入 TailwindCSS | 冰川蓝主题系统已完善，改 Tailwind 成本高且无增益 |
| 维持 ECharts 而非 Recharts | ECharts 功能更强，已集成，`AnalyticsView.vue` 已使用 |
| 阶段 3 引入 WebSocket | 当前无实时功能需求，避免过早引入复杂度 |
| 不迁移到 React | 设计文档是 React 但项目是 Vue 3，功能等价实现即可 |
